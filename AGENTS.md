# Agent guidelines

Lumen is a Rust synthesizer that loads Serum 2 presets and aims to sound like
Serum 2. Read [README.md](README.md) first, then
[docs/PARITY.md](docs/PARITY.md) (what is implemented),
[docs/NEXT_STEPS.md](docs/NEXT_STEPS.md) (the roadmap) and
[docs/CALIBRATION.md](docs/CALIBRATION.md) (how behaviour is measured).

## Clean-room rules

These are not negotiable.

- Match Serum's behaviour by **black-box measurement only**: parameter oracles,
  render comparisons and published preset/file formats. Never translate,
  paraphrase or port decompiled or disassembled code.
- **Never commit Xfer content**: presets, wavetables, samples, multisamples,
  impulses, skins or plugin binaries. The repository is public. Tests that need
  real factory content read the user's local library from an environment
  variable and skip when it is unset.
- Test fixtures must be generated by our own code or scripts, under the
  project licence.
- Record each calibration finding with its evidence (probe, measurement, score)
  in `docs/CALIBRATION.md`. Label guesses as approximate in
  `docs/PARITY.md`.

## Layout

| Crate | Owns |
|---|---|
| `crates/preset` | XferJson container and CBOR codec. Must stay byte-exact on round trip. |
| `crates/dsp` | Engine-agnostic DSP: wavetables, oscillators, warps, sampler, filters, envelopes, LFOs, effect primitives, WAV reading. |
| `crates/engine` | Preset → `Patch` mapping, parameter tables, modulation, voices, FX racks, SFZ, asset loading, offline rendering. |
| `crates/render` | `lumen-render` CLI: render a preset, or `--survey` a library. |
| `crates/compare` | `lumen-compare`: job lists and reports for Serum-vs-Lumen comparison. |
| `crates/plugin` | nih-plug CLAP/VST3 plugin, egui editor (`gui`), standalone app (`standalone`). |

`crates/engine/src/params/serum2.rs` is **generated**. Change
`tools/gen_params.py` or the measured data in `data/`, then regenerate. Do not
edit it by hand. Parameter indices follow Serum's own order because mod slots
address parameters by index.

## Build and test

```bash
cargo test --workspace                       # Linux/WSL
cargo clippy --workspace --all-targets       # must be warning-free
cargo build --release -p lumen-plugin        # CLAP without the editor
```

- **The `gui` and `standalone` features need X11/OpenGL development
  libraries on Linux.** WSL here lacks them, so check editor code on Windows.
- **Windows build:** `tools\build-windows.cmd` uses a user-level
  `x86_64-pc-windows-gnu` Rust with a portable MinGW-w64, and produces
  `target\bundled\` (`Lumen.clap`, `Lumen.vst3`, `lumen-standalone.exe`).
  The usual flow is to rsync the source from WSL to a Windows folder and build
  there.
  - Pass paths to `cmd.exe` through a file, not as arguments. WSL interop
    mangles embedded quotes.
- **Host check:** `tools/host_check.py` loads the VST3 in pedalboard. It checks
  rendering, that host parameter changes take effect, and state restore.
- **Plugin validation:** `clap-validator validate Lumen.clap` must show only
  the four known upstream nih-plug failures listed in the README.
- **Factory-library checks** (local only):
  - `LUMEN_PRESET_DIR=<library>/Presets cargo test -p lumen-preset`
  - `cargo run --release -p lumen-render -- --survey <library>/Presets`
  - Neither may regress in load errors, non-finite output or silent presets.

## Calibration loop

1. Generate probes with `node tools/make_probes.mjs` (each is Serum's init
   state with one change), or pick factory presets with `lumen-compare jobs`.
2. Render the references with `tools/serum_render.py` on Windows. It needs the
   user's own Serum install.
3. Run `lumen-compare report`. Compare scores before and after a change. A
   change that improves one probe set must not regress the others
   (oscillator, FX, warp, sample).

## Code conventions

- **Match the surrounding code:** dense, sparse comments that explain *why*,
  and named `ParamRef` constants instead of string lookups in hot paths.
- **The audio thread must not allocate, lock or do I/O.**
  - Build patches and effect racks off-thread (`PreparedPatch`).
  - Hand them over with `try_lock`.
  - Free retired patches off the audio thread.
- **Parse at the boundary:**
  - Asset paths resolve only inside the library (`tables::resolve_within`).
  - Unknown preset fields are counted in `Coverage`, never silently dropped.
- **Tests:** add a regression test with every bug fix. Prefer tests that work
  without Serum or its assets.
- **Commits:** Conventional Commit subjects (`feat:`, `fix:`, `docs:` …).
- **Keep the docs current:** update the README status, `PARITY.md` and
  `CALIBRATION.md` when behaviour or coverage changes.
